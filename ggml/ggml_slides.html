GGML Tensor Library

用于机器学习的极简张量库

库概述

GGML (Giant Model Language) 是一个专为机器学习任务设计的轻量级张量库，是 llama.cpp 项目的核心组件。

张量操作

提供一套完整的张量运算函数，支持各种机器学习算法的实现。

自动求导

内置自动微分功能，便于梯度计算和模型训练。

基本优化算法

包含常用的优化方法，支持模型参数的更新。

库的目标是为各种机器学习任务提供最小化的方法，包括但不限于：

  • 线性回归
  • 支持向量机
  • 神经网络

核心概念： 使用计算图来表示函数定义，其中每个张量操作对应图中的一个节点。

张量结构与内存布局

理解 GGML 中数据是如何存储和访问的

ggml_tensor 结构体

张量在内存中通过 ggml_tensor 结构体存储，包含关键信息：

struct ggml_tensor { enum ggml_type type; // 数据类型 (F32, F16, Q4_0, 等) int32_t ne[4]; // 每个维度的元素数量 int32_t nb[4]; // 每个维度的字节数 (stride) void* data; // 指向实际数据的指针 struct ggml_tensor* src[2]; // 源张量指针 (用于构建计算图) // ... 其他字段 };

多维张量存储

库支持多达 4 维的张量，采用 行主序 存储方式。通过 ne[] 和 nb[] 数组描述张量的形状和步长。

内存布局示例 (2x3 矩阵):
元素顺序: [0,0] [0,1] [0,2] [1,0] [1,1] [1,2]
步长 nb[0] = sizeof(float), nb[1] = 3 * sizeof(float)

数据访问方式

可以通过直接指针操作访问张量数据：

const int nx = 2; const int ny = 3; struct ggml_tensor * a = ggml_new_tensor_2d(ctx, GGML_TYPE_F32, nx, ny); for (int y = 0; y < ny; y++) { for (int x = 0; x < nx; x++) { *(float *) ((char *) a->data + y*a->nb[1] + x*a->nb[0]) = x + y; } }

或者使用辅助函数：

// 设置一维张量的值 ggml_set_f32_1d(tensor, index, value); // 读取一维张量的值 float value = ggml_get_f32_1d(tensor, index);

计算图基础

GGML 如何表示和执行计算

延迟计算原则

在 GGML 中，定义函数和实际计算是分离的：

  • 第一阶段： 定义计算图（不执行实际计算）
  • 第二阶段： 显式请求时才执行计算

示例: f(x) = a*x² + b

// 阶段1: 构建计算图 { struct ggml_init_params params = { .mem_size = 16*1024*1024, .mem_buffer = NULL, }; struct ggml_context * ctx = ggml_init(params); struct ggml_tensor * x = ggml_new_tensor_1d(ctx, GGML_TYPE_F32, 1); ggml_set_param(ctx, x); // 标记 x 为输入变量 struct ggml_tensor * a = ggml_new_tensor_1d(ctx, GGML_TYPE_F32, 1); struct ggml_tensor * b = ggml_new_tensor_1d(ctx, GGML_TYPE_F32, 1); struct ggml_tensor * x2 = ggml_mul(ctx, x, x); // x² struct ggml_tensor * f = ggml_add(ctx, ggml_mul(ctx, a, x2), b); // a*x² + b // 到目前为止，只有图的定义，没有实际数值计算 } // 阶段2: 执行计算 { struct ggml_cgraph * gf = ggml_new_graph(ctx); ggml_build_forward_expand(gf, f); // 构建前向传播图 // 设置输入和参数值 ggml_set_f32(x, 2.0f); ggml_set_f32(a, 3.0f); ggml_set_f32(b, 4.0f); // 执行计算 ggml_graph_compute_with_ctx(ctx, &gf, n_threads); // 获取结果 float result = ggml_get_f32_1d(f, 0); // 应该是 3*4 + 4 = 16 printf("f = %f\n", result); }

计算图的优势

这种设计带来了几个重要优势：

内存效率

所有计算使用在 ggml_init() 中分配的单一内存缓冲区，避免运行时内存分配开销。

可重用性

函数图只需定义一次，可多次计算前向传播和反向传播（梯度）。

灵活性

可以轻松修改输入值并重新计算，而无需重建整个图。

核心操作与自动求导

GGML 如何实现张量运算和梯度计算

基本运算分类

GGML 的操作主要分为两类：

一元操作 (Unary)

单输入张量操作，如：
ggml_relu, ggml_sigmoid, ggml_sqrt

二元操作 (Binary)

双输入张量操作，如：
ggml_add, ggml_mul, ggml_div

复杂操作示例

虽然库最初设计仅支持一元和二元操作，但后来扩展了更复杂的操作：

// 维度置换操作 struct ggml_tensor * ggml_permute(struct ggml_context * ctx, struct ggml_tensor * src, int32_t axis0, int32_t axis1, int32_t axis2, int32_t axis3); // 一维卷积（步长1） struct ggml_tensor * ggml_conv_1d_1s(struct ggml_context * ctx, struct ggml_tensor * weight, struct ggml_tensor * src); // 矩阵乘法 struct ggml_tensor * ggml_mul_mat(struct ggml_context * ctx, struct ggml_tensor * weight, struct ggml_tensor * src);

自动求导机制

每个张量操作都实现了前向和反向计算函数：

前向传播

计算输出张量值，给定输入张量值：
y = f(x₁, x₂, ...)

反向传播 (Backward)

计算输入张量的导数（伴随），给定输出张量的导数：
∂L/∂xᵢ = (∂L/∂y) * (∂y/∂xᵢ)

数学直觉： 反向传播计算的是损失函数 L 对每个输入张量的偏导数，通过链式法则传递梯度。

硬件后端抽象

GGML 如何支持多种硬件加速器

统一的后端接口

GGML 通过 ggml-backend.h 提供硬件无关的抽象层，使得同一套代码可以在不同硬件平台上运行。

支持的后端

CUDA

NVIDIA GPU 加速
文件: ggml-cuda/*.cu, ggml-cuda/*.cuh

OpenCL

跨平台 GPU/加速卡
文件: ggml-opencl/*.cl, ggml-opencl/*.cpp

Vulkan

现代跨平台 GPU API
文件: ggml-vulkan/*

Metal

苹果平台 GPU 加速
文件: ggml-metal/*

WebGPU

网页平台 GPU 加速
文件: ggml-webgpu/*

CPU 优化

包括 SIMD 指令集优化
文件: ggml-cpu/*, ggml-sycl/*

后端接口设计

每个后端需要实现一组标准操作：

struct ggml_backend { // 内存管理 void (* alloc_buf)(struct ggml_backend * backend, struct ggml_buf * buf); void (* free_buf)(struct ggml_backend * backend, struct ggml_buf * buf); // 异步操作 void (* cpymem)(struct ggml_backend * backend, void * dst, const void * src, size_t size); void (* memset )(struct ggml_backend * backend, void * dst, int value, size_t size); // 操作执行 void (* op)(struct ggml_backend * backend, const struct ggml_cplan * plan, const struct ggml_tensor * tensors[]); // 同步 void (* synchronize)(struct ggml_backend * backend); // 获取后端名称 const char * (* get_name)(struct ggml_backend * backend); };

后端选择与初始化

在初始化上下文时选择后端：

struct ggml_init_params params = { .mem_size = buffer_size, .mem_buffer = buffer, }; // 自动选择最佳可用后端 struct ggml_context * ctx = ggml_init(params); // 或显式指定后端 struct ggml_backend * backend = ggml_backend_cpu_init(); struct ggml_init_params params = { .mem_size = buffer_size, .mem_buffer = buffer, .backend = backend, }; struct ggml_context * ctx = ggml_init(params);

优势： 研究人员可以专注于算法实现，而无需为每种硬件平台编写特定代码。

量化支持

如何通过降低精度来提高效率

为什么需要量化？

大型语言模型包含 billions 个参数，存储和计算需求巨大。量化技术可以：

  • 显著减少模型存储大小（通常减少 2-4 倍）
  • 降低内存带宽需求
  • 在一定程度上加速计算
  • 在资源受限设备上运行大模型成为可能

支持的量化格式

GGML 支持多种量化格式，在 ggml-quants.h 和 ggml-quants.c 中定义：

enum ggml_type { GGML_TYPE_F32 = 0, // 32-bit 浮点 GGML_TYPE_F16 = 1, // 16-bit 浮点 GGML_TYPE_Q4_0 = 2, // 4-bit 量化 (无零点) GGML_TYPE_Q4_1 = 3, // 4-bit 量化 (带零点) GGML_TYPE_Q5_0 = 4, // 5-bit 量化 GGML_TYPE_Q5_1 = 5, // 5-bit 量化 GGML_TYPE_Q8_0 = 6, // 8-bit 量化 GGML_TYPE_Q8_1 = 7, // 8-bit 量化 // ... 更多格式 };

量化张量的内存布局

量化张量使用特殊的内存布局来存储低精度值：

Q4_0 格式示例:
每个字节存储两个 4-bit 值:
[xxxxxxxx] → [xxxx][xxxx] (两个 4-bit 数字)
需要额外的 scales 和可能的零点来恢复近似值

量化操作实现

量化操作在 ggml-quants.c 中实现，包括：

转换函数

在高精度和低精度之间转换：
ggml_quantize_chunk, ggml_dequantize_chunk

量化矩阵乘法

专门优化的量化矩阵运算：
ggml_mul_mat_q4_0, ggml_mul_mat_q4_1 等

其他量化操作

加法、乘法等操作的量化版本
