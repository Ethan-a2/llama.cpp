📋 Project Overview

llama.cpp is a project that provides:

  • ggml: A C++ library for tensor operations and ML inference
  • gguf: A file format for storing quantized ML models
  • Inference engines for LLaMA and other transformer models
  • Multiple backends: CUDA, OpenVINO, WebGPU, and more
  • Python bindings via gguf-py/
Primary use cases: - Run LLMs on CPU/GPU with high performance - Convert and quantize models (GGUF format) - Fine-tune and train models - Deploy models in production

🔧 ggml Core Library

The heart of the project - tensor operations and computational graph

src/ggml-*.c Backend implementations (CUDA, CPU, etc.)
include/ggml/ Public API headers
ggml.c Core graph execution engine
ggml-opt.c Optimization routines
Key capabilities: - Tensor operations (matmul, conv, attention, etc.) - Automatic differentiation - Memory-efficient computation - Multi-device support - Quantization (Q4_0, Q4_1, Q5_0, Q5_1, Q8_0, Q2_K, Q3_K, Q4_K, Q5_K, Q6_K)

🏗️ Backend Architecture

ggml supports multiple computation backends through a unified interface

Backend Implementations in ggml/src/: ═══════════════════════════════════════════════════════ • ggml-cuda.cu → NVIDIA CUDA • ggml-cpu.c → CPU (AVX2, AVX512, ARM NEON) • ggml-openvino.c → Intel OpenVINO • ggml-webgpu.c → WebGPU (browser) • ggml-virtgpu.c → Virtual GPU • ggml-cann.c → Huawei CANN • ggml-zdnn.c → IBM z/OS zdnn • ggml-zendnn.c → AMD ROCm ZenDNN Each backend implements: - Tensor operations - Memory allocation - Graph execution

Runtime selection: Backend chosen at compile-time via CMake options

💾 GGUF Format

GGUF (GPT-Generated Unified Format) - the modern model format

Header Magic, version, tensor count
Metadata Architecture, vocab, params
Tensors Offsets, shapes, quantization
Alignment Optimized for memory mapping
Advantages over old GGML format: ✓ Single file - no separate vocab/tensor files ✓ Extensible metadata (KV pairs) ✓ Supports all quantization types ✓ Fast loading via memory mapping ✓ Versioned and documented ✓ SNAP (IREE) compatible

gguf-py/ ├── gguf/ │ ├── __init__.py │ ├── constants.py # Quantization types, metadata keys │ ├── gguf.py # Main GGUF reader/writer │ ├── vocab.py # Vocabulary handling │ ├── tensor.py # Tensor metadata │ ├── pygraph.py # Graph operations │ ├── cconversion.py # Conversion utilities │ ├── transform.py # Model transformations │ └── dtypes.py # Data type definitions
Key capabilities: • Read/write GGUF files • Inspect model metadata • Convert between formats (HF → GGUF) • Manipulate tensors • Generate and modify vocabularies

🛠️ Command-Line Tools

Essential tools in tools/ directory

  • main - Main inference tool, interactive chat
  • quantize - Quantize models to GGUF
  • perplexity - Calculate model perplexity
  • bench - Performance benchmarking
  • server - HTTP server for model serving
  • mtmd - Multi-token prediction demo
  • embedding - Generate embeddings
  • xml2json - Convert prompts
Example usage: $ ./main -m model.gguf -p "Hello, world!" $ ./quantize model.f16.gguf model-q4_0.gguf Q4_0 $ ./server -m model.gguf --port 8080

🔄 Model Conversion Scripts

Convert models from various frameworks to GGUF

convert_hf_to_gguf.py HuggingFace → GGUF
convert_llama_ggml_to_gguf.py Old GGML → GGUF
convert_lora_to_gguf.py LoRA adapters → GGUF
Conversion workflow: 1. Load source model (HF PyTorch/GGML) 2. Extract weights, architecture, vocab 3. Apply quantization if needed 4. Write GGUF with metadata 5. Validate and optimize Python script uses gguf-py library

🔨 Build System

CMake-based build with multiple configuration options

CMakeLists.txt Main build configuration

ggml/CMakeLists.txt Library build

Key build options: • GGML_BACKEND=CPU|CUDA|OPENVINO|... • GGML_STATIC=ON|OFF (static/shared lib) • BUILD_SHARED_LIBS=ON|OFF • CMAKE_BUILD_TYPE=Release|Debug • GGML_NATIVE=ON|OFF (CPU optimizations) Build: mkdir build && cmake .. && make -j
